Practice

  1. Write the Day 3 enclosure in CadQuery, with the Pi board as a simple box inside it.
  2. Put every size in variables at the top (board size, wall, clearance).
  3. Check for collisions: intersect the board with the enclosure and confirm the result is empty.
  4. Push the script to a GitHub repo with a README that explains each variable.

Collision and clearance check in code

def clash_volume(a, b):
    "Volume (mm³) where two solids overlap; 0 means no collision."
    try:
        return a.intersect(b).val().Volume()
    except Exception:
        return 0.0

board = cq.Workplane("XY").box(85, 56, 1.6).translate((0, 0, FLOOR + STANDOFF))
# clearance check: make the board bigger by the gap we want, then test
board_plus_gap = cq.Workplane("XY").box(85 + 2*GAP, 56 + 2*GAP, 1.6).translate((0, 0, FLOOR + STANDOFF))

v = clash_volume(board_plus_gap, enclosure)
print("no collision" if v < 0.001 else f"COLLISION: {v:.2f} mm³")
assert v < 0.001

Testing the board plus its gap checks two things at once: it doesn't hit the walls, and it has the clearance you planned.

Assemblies

An cq.Assembly holds several parts, each with a position and a colour, and saves them together as one STEP file:

assy = (cq.Assembly()
        .add(enclosure, name="case", color=cq.Color("gray"))
        .add(board, name="pi5", color=cq.Color("green")))
assy.save("pi-box.step")

A README that explains the variables

# pi-box

Script-driven enclosure for a Raspberry Pi 5.

| Variable | Default | Meaning |
|----------|---------|---------|
| WALL     | 2.0     | wall thickness, mm |
| GAP      | 0.5     | clearance around the board, mm |
| STANDOFF | 3.0     | height of the board above the floor, mm |

Run: `~/cq/bin/python pi_box.py` → prints the collision check, writes pi-box.step

With Claude: the 3D Concept method in a session

When there's a new machine or system idea at DiGiKits, the first step is a 3D Concept with Claude: a script-driven page at real scale, collision-checked, that everyone can open and turn. DiGiKits has saved Claude skills (written instructions Claude loads) so it follows the same method every time.

3D Concept: a wall box for one DiGiKits LED controller.
Inside: a Pico 2 board (51 x 21 mm), a network module (50 x 25 x 22 mm),
a 5 V 10 A supply (110 x 78 x 36 mm), a fuse holder, two cable glands at the bottom.
Box inner size to be found: as small as possible with 10 mm gaps between parts.
Before building, list your assumptions and questions. Then:
one script, all sizes named at the top, parts placed in 3D,
a clash check between every pair (report each clash and its volume),
and a 3D page I can orbit on my phone.

Numbers in these prompts are examples. Always take sizes from your own parts' datasheets or your calipers.

Review the page, then send all your changes in one message ("supply on the left, glands 40 mm apart, add a vent above the supply"). One round of many changes is faster than many rounds of one change.

Before you accept Claude's work, check:

  • The clash check really ran and reports zero (read the output, don't trust the summary).
  • Every assumption Claude listed now has a real number or a decision from you.
  • Sizes come from datasheets or measurement, not from memory (Claude's or yours).

Done when

  • The assembly script runs and reports "no collision"
  • The script is on GitHub
  • Your script checks the board plus its gap against the enclosure
  • The assembly saves both parts in one STEP file with colours
  • Your README lists every variable with its meaning
  • You ran a 3D Concept session: assumptions, page, clash check, one review round

More cases

Try each one before you open the answer.

The check says “no collision”, but the printed board won't fit.

Something in the model isn't real: a connector or the cooler is missing from the board box. Add the tall parts as simple boxes and check again.

You set GAP to 0.5 and the check reports a collision of 340 mm³.

The gap hits the walls: the inside of the box is too small for board + 2 × GAP. Grow the inside, or calculate it from the board size and GAP so it can't happen.

Two people edited the same script and the sizes are confusing.

Parameters at the top, changes through pull requests (Phase 2 Day 10): the diff shows exactly which number changed and why.
