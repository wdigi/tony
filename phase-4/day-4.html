Phase 4 · Day 4

Script-driven 3D, part 1

Build 3D models from code instead of clicks. This is how DiGiKits makes fast, exact 3D concepts.

📝Update progress on the message board below ↓

Why code?

A model written as code can be changed by editing one number, checked automatically, kept on GitHub, and generated by AI. DiGiKits builds concepts at real scale in code before anyone buys parts.

Practice (CadQuery)

Install CadQuery in a Python virtual environment (follow its install page; it needs a supported Python version):

python3 -m venv ~/cq && ~/cq/bin/pip install cadquery
import cadquery as cq

plate = (cq.Workplane("XY")
         .box(100, 60, 3)
         .edges("|Z").fillet(2)
         .faces(">Z").workplane()
         .rect(90, 50, forConstruction=True).vertices()
         .hole(3.2))
cq.exporters.export(plate, "plate.step")
cq.exporters.export(plate, "plate.stl")

Open the STEP file in FreeCAD and compare it with your Day 2 plate.

Selectors: pointing at faces and edges

In code you can't click a face, so you describe it:

SelectorMeans
">Z"The face furthest up (top)
"<Z"The face furthest down (bottom)
">X", "<Y"Furthest right, furthest front, and so on
"|Z"Edges parallel to Z (the upright edges of a box)
"#Z"Edges perpendicular to Z

Parameters on top, always

import cadquery as cq

LENGTH, WIDTH, THICK = 100, 60, 3     # mm
HOLE_D, INSET = 3.2, 5                # hole size, distance from the edge
CORNER_R = 2

plate = (cq.Workplane("XY")
         .box(LENGTH, WIDTH, THICK)
         .edges("|Z").fillet(CORNER_R)
         .faces(">Z").workplane()
         .rect(LENGTH - 2 * INSET, WIDTH - 2 * INSET, forConstruction=True).vertices()
         .hole(HOLE_D))

bb = plate.val().BoundingBox()
print(f"size: {bb.xlen:.1f} x {bb.ylen:.1f} x {bb.zlen:.1f} mm")
assert abs(bb.xlen - LENGTH) < 0.01, "length is wrong"
cq.exporters.export(plate, "plate.step")

AI and CadQuery

Because a model is just text, Claude can write and change CadQuery for you: "Make the plate 120 mm long and add a 10 mm slot in the middle." Treat it like any AI code (Phase 3 Day 6): read it, run it, and check the size with the bounding box or by measuring the STEP in FreeCAD. Then commit it to GitHub so every version is kept.

With Claude: Claude writes the CadQuery

This is the heart of how DiGiKits builds concepts: Claude writes the script, you give the numbers and check the result. A good request has the same five parts every time:

Write a CadQuery script for a mounting plate.
Goal: holds a Pico 2 and a network module side by side on a wall.
Numbers: plate 120 x 70 x 3 mm, corner radius 4; Pico holes 2.1 mm at 11.4 x 47.0 mm spacing;
module holes 3.2 mm at 60 x 30 mm spacing; 10 mm between the two boards; 4 wall holes 4.5 mm, 6 mm in.
Structure: every size as a named parameter at the top with a comment.
Self-check: print the bounding box and assert the plate size.
Output: plate.step and plate.stl.

Numbers in these prompts are examples. Always take sizes from your own parts' datasheets or your calipers.

Then change it by talking

"Make the wall holes countersunk for 4 mm screws." "Move the module 5 mm up." Each change comes back as a new script; commit each one so git diff shows exactly which numbers moved.

Claude Code: Claude runs it too

In the Claude app Claude writes the script and you run it. With Claude Code, Claude can also run the script itself, read the error, fix it, and commit to your GitHub repo, while you watch from a laptop or a phone. That's how most DiGiKits building happens: you direct and review, Claude does the typing and the re-running.

Before you accept Claude's work, check:

  • The script runs and prints the right bounding box.
  • Each named number matches your list (Claude can swap two numbers).
  • Opened in FreeCAD, two hole spacings measure right.
  • The commit message says what changed and why.

Done when

  • Your Day 2 plate rebuilt from code
  • Changing one number in the code changes the part
  • Every size in your script is a named parameter at the top
  • Your script prints the bounding box and asserts the length
  • You asked Claude for a change and verified the result before committing
  • Claude wrote a CadQuery part from your five-part request, and it passed its own size check
  • You changed the part twice by talking, and each change is a separate commit

More cases

Try each one before you open the answer.

The holes come out on the bottom instead of the top.

The workplane was on the wrong face. Check the selector: faces(">Z") is the top.

pip install cadquery fails with errors about the Python version.

CadQuery supports only certain Python versions. Make the venv with a supported Python (see CadQuery's install page) or use the method it recommends.

Claude's script runs, but the plate is 10 mm too short.

It probably used the size somewhere it shouldn't (for example subtracting the inset twice). The bounding-box print caught it: read the code line by line and fix it.
