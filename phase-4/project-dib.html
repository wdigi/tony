Phase 4 · Your project

Virtual Driving School (DIB)

Your Phase 4 project, chosen by your coach: build a 3D town where a learner drives a car and learns the rules of the road, step by step, using everything from the 3D track.

📝Update progress on the message board below ↓

What it is

Your project is a virtual town in 3D: a learner drives a car through it in the browser, and the program notices what they did right and wrong at lights, stop signs and speed limits.

This page covers your technical work only. Everything else about DIB stays with your coach.

How the city should look

Start from a city file

// city.json  - the whole city is data; the code just builds what's listed
{
  "units": "metres",
  "lane_width": 3.5,
  "roads": [
    { "from": [0, 0],   "to": [200, 0],   "lanes": 2, "speed_limit": 50 },
    { "from": [100, -80], "to": [100, 80], "lanes": 2, "speed_limit": 40 }
  ],
  "intersections": [ { "at": [100, 0], "control": "traffic_light" } ],
  "buildings": [ { "at": [40, 20], "size": [12, 10, 7], "type": "house" } ],
  "trees":     [ [30, -12], [55, -12], [150, 14] ]
}

Your code reads this file and builds roads, buildings and trees from it. Adding a street means adding a line, not writing new code.

With Claude: building DIB

Build every milestone with Claude, the way the track taught you. Start the repo with a NOTES.md holding the design rules above (sunny, low-rise, only city, metres, Y up, Ontario rules, data-driven), so every session begins with them.

Read NOTES.md and city.json. Build milestone 1 as one HTML page with Three.js 0.170:
build roads, houses and trees from city.json at real scale (metres, Y up),
sunny daylight with soft shadows, orbit camera, a 10 m ground grid I can switch off.
Before you build, list anything in city.json or NOTES.md that's unclear.
Keep the city-building code separate from the scene setup, so later milestones
can reuse it. Explain each part in one line.

Working tips

Try each one before you open the answer.

The car looks tiny, or the houses look huge.

Something isn't in metres. Check every size against real life: lane 3.5 m, car 4.5 × 1.8 m, a house about 10 m wide (Day 1).

It's smooth on the laptop and jerky on the Pi.

Too many triangles or shadows. Simplify buildings to boxes with good colours, limit shadows to the sun, and test on the Pi every milestone, not at the end.

You want to add a feature that isn't on the list.

Write it down as a GitHub issue labelled "later" and keep going with the current milestone. Ask your coach before switching.

Claude wrote the whole car physics for you, and it almost works.

Ask for smaller pieces you can understand: first just moving forward, then turning, then stopping at houses. Test each before the next (Phase 3 Day 6).
