Phase 2 · Day 2

Scheduled jobs

Make the Pi run checks on its own, on a schedule, and keep a log.

📝Update progress on the message board below ↓

Why it matters

Machines in a showroom or the lab run for weeks. Scheduled checks catch problems before a customer does.

Practice

Run your health script every 10 minutes with cron:

crontab -e
# add this line:
*/10 * * * * /home/yourname/bin/health.sh >> /home/yourname/health.log 2>&1

Then do the same job with a systemd timer, the more modern way. Create /etc/systemd/system/health.service and health.timer:

# health.service
[Service]
Type=oneshot
ExecStart=/home/yourname/bin/health.sh
User=yourname

# health.timer
[Timer]
OnBootSec=2min
OnUnitActiveSec=10min
[Install]
WantedBy=timers.target
sudo systemctl daemon-reload
sudo systemctl enable --now health.timer
systemctl list-timers
journalctl -u health -n 20

More cron times

Line starts withRuns
*/10 * * * *Every 10 minutes
0 9 * * 1-509:00, Monday to Friday
30 2 * * 002:30 every Sunday
0 */6 * * *Every 6 hours, on the hour
@rebootOnce, at every start-up

Not sure? Paste the five fields into a "cron expression explainer" website, or ask Claude, and check the plain-English answer.

Why jobs work in the terminal but not in cron

Timers in more depth

# health.timer, run at fixed clock times instead
[Timer]
OnCalendar=Mon..Fri 09:00
OnCalendar=*-*-* 18:00:00
Persistent=true          # if the Pi was off at 09:00, run once when it comes back
[Install]
WantedBy=timers.target
systemd-analyze calendar "Mon..Fri 09:00"   # check: when is the next run?
systemctl list-timers --all                 # every timer, last and next run
timedatectl                                 # the Pi's clock and time zone

A timer runs on the Pi's own clock and time zone. If it's still set to UTC, "09:00" happens at 4 a.m. Toronto time. Set it with sudo raspi-config → Localisation → Timezone.

Stop logs filling the card

A log that gets a line every 10 minutes grows forever. logrotate keeps it small: each week it starts a new file and deletes old ones.

# /etc/logrotate.d/health   (create with sudo nano)
/home/tony/health.log {
    weekly
    rotate 4          # keep 4 old weeks
    compress
    missingok
    notifempty
}

Test it: sudo logrotate -d /etc/logrotate.d/health (dry run, changes nothing).

Done when

  • The log grows by one line every 10 minutes
  • You can explain when to use cron and when a timer
  • You wrote cron lines for 09:00 weekdays and for every boot
  • Your timer uses OnCalendar with Persistent=true, checked with systemd-analyze
  • The Pi's time zone is right (timedatectl)
  • Your health log is rotated by logrotate

Support drill

The cron job never runs. Find out why (hint: paths and permissions inside cron are not the same as in your terminal).

More cases

Try each one before you open the answer.

The cron log shows the date and host, but temp and power are empty.

vcgencmd isn't found with cron's short PATH. Use /usr/bin/vcgencmd in the script, or set PATH=… at the top of the crontab.

The showroom Pi was off at 09:00 and the morning job never ran.

Add Persistent=true to the timer: it catches up when the Pi starts.

The TV switches on at 4 a.m. instead of 9.

The Pi's time zone is UTC. timedatectl shows it; set America/Toronto (or the client's zone).

The card is full, and health.log is 2 GB.

No log rotation. Move the old file away, add a logrotate rule, and check other logs with du -sh /var/log/* ~/*.log.
