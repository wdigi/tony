Phase 2 · Day 1

Shell scripts

Turn commands you type into scripts that do the work for you.

📝Update progress on the message board below ↓

Why it matters

Support work repeats. A script does the same check the same way every time, at 3 a.m. too.

Practice

Create ~/bin/health.sh:

#!/bin/bash
# health.sh - one-line health report for this Pi
host=$(hostname)
temp=$(vcgencmd measure_temp | cut -d= -f2)
disk=$(df -h / | awk 'NR==2 {print $5}')
power=$(vcgencmd get_throttled | cut -d= -f2)
echo "$(date '+%F %T') $host temp=$temp disk=$disk power=$power"
chmod +x ~/bin/health.sh
~/bin/health.sh

Then add an if: print WARNING when the disk is over 80% full. Add a for loop that pings three addresses and prints which ones answer.

The building blocks

WriteMeans
name="trainpi"Set a variable. No spaces around =.
"$name"Use it. Always in double quotes, so spaces in values don't break things.
$(hostname)Run a command and use its output
$1, $2, $#The first and second words after the script name; how many there are
$?The exit code of the last command: 0 = worked, anything else = failed
cmd1 && cmd2Run cmd2 only if cmd1 worked
cmd1 || cmd2Run cmd2 only if cmd1 failed

A safer health script

#!/bin/bash
# health.sh - one line about this Pi; exits 1 if something needs attention
set -u                            # stop on typos in variable names
limit=${1:-80}                    # disk limit in %, default 80
disk=$(df --output=pcent / | tail -1 | tr -dc '0-9')
power=$(vcgencmd get_throttled | cut -d= -f2)
status=OK
if [ "$disk" -gt "$limit" ]; then status=WARNING; fi
if [ "$power" != "0x0" ]; then status=WARNING; fi
echo "$(date '+%F %T') $(hostname) disk=${disk}% power=$power $status"
[ "$status" = OK ]                # the script's own exit code: 0 or 1

Run ~/bin/health.sh 5 to test the warning with a low limit.

Finding faults in scripts

sudo apt install -y shellcheck
shellcheck ~/bin/health.sh        # points out common mistakes, line by line

Run it by name from anywhere

The terminal looks for programs in the folders listed in $PATH. Raspberry Pi OS adds ~/bin when it exists at login, so after you log in again health.sh works from any folder. Otherwise run it with its path: ~/bin/health.sh or ./health.sh.

Done when

  • Your script prints one clear line about the Pi
  • It warns when the disk is too full (test it by lowering the limit)
  • You can explain $?, && and || with an example
  • Your script takes the disk limit as $1 and exits 1 on WARNING
  • You traced your script with bash -x
  • shellcheck reports no problems

Support drill

A script says "Permission denied" and another says "command not found". Fix both.

More cases

Try each one before you open the answer.

“/bin/bash^M: bad interpreter”.

The script was saved on Windows, which ends lines with an extra hidden character. Fix: sed -i 's/\r$//' script.sh, and set your editor to Unix (LF) line endings.

[: missing `]'

Brackets need spaces inside: [ "$disk" -gt 80 ], not ["$disk" -gt 80].

A script breaks only when a file name has a space.

A variable used without quotes. Write "$file" everywhere. shellcheck finds every one.

The script runs without errors but prints nothing.

Run it with bash -x and read which branch it took. Then check echo $? right after the commands it depends on.
