Phase 2 · Day 5

Network services and ports

See what is listening on a Pi, talk to it directly, and keep it safe with a firewall.

Why it matters

The DiGiKits LED Controller takes plain-text commands over the network. Many faults are "it is running, but nothing can reach it".

Practice

sudo ss -tlnp                 # what is listening, on which port
sudo apt install netcat-openbsd
nc -zv trainpi 22             # is port 22 open?

Write a tiny fake LED controller in Python that listens on port 5000:

import socketserver

class Handler(socketserver.StreamRequestHandler):
    def handle(self):
        for line in self.rfile:
            cmd = line.decode().strip()
            print("got:", cmd)
            self.wfile.write(f"OK {cmd}\n".encode())

socketserver.TCPServer.allow_reuse_address = True
socketserver.TCPServer(("0.0.0.0", 5000), Handler).serve_forever()

From your laptop: nc trainpi 5000, then type RED and press Enter.

Firewall

sudo apt install ufw
sudo ufw allow ssh          # FIRST, or you lock yourself out
sudo ufw allow 5000/tcp
sudo ufw enable
sudo ufw status

Done when

  • Your laptop sends a command and gets "OK" back
  • The firewall is on and SSH still works

Support drill

The fake controller runs, but the laptop can't connect. Find it: wrong port, firewall, or listening on 127.0.0.1 only?
