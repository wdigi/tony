Phase 2 · Day 12

Managing many Pis

Look after ten Pis as easily as one.

Why it matters

The lab and client sites have many computers. Doing everything by hand on each one is slow and causes mistakes.

Practice

Give each Pi a short name in ~/.ssh/config on your laptop:

Host screen1
    HostName trainpi
    User yourname
ssh screen1 uptime
scp file.txt screen1:~/              # copy one file
rsync -av ~/site/ screen1:~/site/    # copy a folder, only what changed
for h in screen1 screen2; do ssh "$h" 'hostname; vcgencmd measure_temp'; done

Use a second SD card (or a second Pi) as "screen2" so the loop really talks to two machines.

Done when

  • One command shows the temperature of two Pis
  • You update a web page on both with one rsync loop

Support drill

The loop hangs on one machine. Add a timeout (ssh -o ConnectTimeout=5) and make it report which host failed.
