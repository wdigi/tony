Phase 2 · Day 8

Docker, part 1

Run software in containers: packaged apps that work the same on every machine.

📝Update progress on the message board below ↓

Why it matters

DiGiKits software is shipped and updated as containers. "It worked on my machine" stops being a problem.

Practice

curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER     # then log out and back in
docker run hello-world
docker run -d --name web -p 8080:80 nginx
docker ps
docker logs web
docker stop web && docker rm web

Open http://trainpi:8080 from your laptop while the container runs.

Serve your own page: put an index.html in ~/site and run

docker run -d --name web -p 8080:80 -v ~/site:/usr/share/nginx/html:ro nginx

Learn the words

Image (the package), container (a running copy), port mapping (8080 outside → 80 inside), volume (a folder shared with the container).

A container's life

Everyday Docker commands

CommandDoes
docker ps -aAll containers, also stopped ones
docker logs -f webFollow a container's output
docker exec -it web shOpen a shell inside a running container (exit to leave)
docker statsLive CPU and memory per container
docker imagesImages stored on this Pi
docker system dfHow much disk Docker uses
docker system pruneDelete stopped containers and unused images (asks first)

Tags and restart policies

  • Tags name a version: nginx:1.27. latest just means "whatever is newest today", so it can change under you. DiGiKits pins exact versions.
  • Architecture: the Pi is arm64. An image built only for PCs (amd64) won't run on it.
  • Restart policy: docker run -d --restart unless-stopped … brings the container back after a crash or a reboot, like Restart=always in systemd.

Done when

  • Your own page is served from a container
  • You can explain image, container, port and volume
  • You opened a shell inside a running container and left again
  • Your web container comes back after a reboot (restart policy)
  • You can explain why a tag like nginx:1.27 is safer than latest

Support drill

"Port is already allocated." Find what's using it and fix it.

More cases

Try each one before you open the answer.

“exec format error” when a container starts.

The image was built for PCs (amd64), not the Pi (arm64). Use an image that supports arm64, or build it for arm64.

“permission denied while trying to connect to the Docker daemon socket”.

Your user isn't in the docker group yet, or you didn't log in again after adding it.

The container is gone after a reboot.

It was started without a restart policy. Run it again with --restart unless-stopped (Day 9 puts this in a Compose file).

You edited a file inside the container, then removed it; the change is lost.

That's how containers work. Put files that must survive in a volume, or change the image itself.
