Phase 2 · Day 10

GitHub for teams

Work on shared files the way a team does: branches, pull requests and issues.

📝Update progress on the message board below ↓

Why it matters

Nobody edits DiGiKits code or guides directly on the main copy. Changes are proposed, reviewed, then merged.

Practice

git switch -c fix-typo          # a new branch
nano README.md
git commit -am "Fix typo in README"
git push -u origin fix-typo
  1. On GitHub, open a pull request from your branch. Describe what and why in two lines.
  2. Your coach reviews it and asks for one change. Make it on the same branch and push again.
  3. After approval, merge it, then delete the branch.
  4. Open an issue for a problem you found in this training site. Reference it in a pull request with "Fixes #N".

A pull request people want to review

  • Small: one change, one reason. Ten small PRs are reviewed faster than one huge one.
  • Clear title: "Fix wrong pin number in blink guide", not "updates".
  • Description: what changed, why, how you tested it, anything the reviewer should look at.
  • Answer every review comment: fix it, or explain why not. Then push to the same branch; the PR updates by itself.

Merge conflicts

When two people change the same lines, Git can't choose. It marks the spot and asks you:

Not sure which version is right? Ask the person who wrote the other one. That's what the PR comments are for.

Writing an issue someone can act on

Keep your branch fresh

git switch main && git pull           # get the latest main
git switch fix-typo
git merge main                         # bring main's new changes into your branch
git push

Done when

  • You merged a reviewed pull request
  • One of your pull requests closed an issue
  • You resolved a merge conflict on purpose (your coach makes one for you)
  • Your PR description says what, why and how you tested
  • You wrote an issue with steps, expected, actual, where and evidence

Support drill

Your push is rejected because the remote has new commits. Pull, fix any conflict, and push.

More cases

Try each one before you open the answer.

You made two commits on main by mistake (not pushed yet).

Make a branch where you are: git switch -c my-fix, push that, and open a PR. Then reset your local main to GitHub's: git switch main, git reset --hard origin/main (only because those commits now live on the branch).

Your PR shows 200 changed files, but you changed one.

Line endings or file permissions changed everywhere (often from editing on Windows), or the branch started from the wrong place. Look at one of the files' diffs; ask your coach before merging.

The reviewer asked for changes. Do you open a new PR?

No. Commit the changes on the same branch and push. The PR updates, and the conversation stays in one place.

Conflict markers got committed by accident.

Search for them: grep -rn '<<<<<<<' .. Fix the files, commit again.
