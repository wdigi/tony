Phase 2 · Day 11

Writing setup guides

Write a guide so clear that someone else can set up a system without calling you.

Why it matters

Every DiGiKits product needs a setup guide and a fix-it guide. You will write and improve many of them.

Rules for a good guide

  • Say at the top what it sets up, what you need, and how long it takes.
  • One action per numbered step. Exact commands in code blocks.
  • After important steps, say what you should see ("the page fills the screen").
  • End with "If it doesn't work" for the three most likely faults.

Practice

Turn your Day 3–4 notes into big-screen-setup.md in a GitHub repo, written in Markdown. Then hand it to someone else (or follow it yourself on a fresh card without your notes) and fix every place they got stuck.

Done when

  • The guide is on GitHub in Markdown
  • It was tested on a fresh card and fixed

Support drill

Read an old guide your coach gives you. Find three steps that would confuse a new person and fix them.
