Phase 2 · Day 11

Writing setup guides

Write a guide so clear that someone else can set up a system without calling you.

📝Update progress on the message board below ↓

Why it matters

Every DiGiKits product needs a setup guide and a fix-it guide. You will write and improve many of them.

Rules for a good guide

  • Say at the top what it sets up, what you need, and how long it takes.
  • One action per numbered step. Exact commands in code blocks.
  • After important steps, say what you should see ("the page fills the screen").
  • End with "If it doesn't work" for the three most likely faults.

Practice

Turn your Day 3–4 notes into big-screen-setup.md in a GitHub repo, written in Markdown. Then hand it to someone else (or follow it yourself on a fresh card without your notes) and fix every place they got stuck.

The DiGiKits guide shape

Writing that works at 3 a.m.

Instead ofWrite
Configure the network appropriately.Open sudo nmtui → Activate a connection → choose DGK-LAB.
Simply restart the service.Run sudo systemctl restart kiosk. The screen goes black for about 10 seconds.
Ensure power is adequate.Use the 27 W official supply. A phone charger is not enough.
Make sure it's working.The page fills the screen with no address bar.
  • Start each step with a verb: Open, Type, Plug, Wait.
  • Put the warning before the risky step, not after.
  • Avoid "just" and "simply": if the reader is stuck, those words make it worse.
  • A labelled photo beats a paragraph about which cable goes where.

Using AI to write guides

Claude is good at turning your rough notes into a clean draft in the template above. It has never seen your Pi, though: it can invent a menu name or a flag that doesn't exist. Test every step yourself before the guide goes to anyone.

Done when

  • The guide is on GitHub in Markdown
  • It was tested on a fresh card and fixed
  • Your guide follows the five-part shape
  • Each step starts with a verb and has an exact command or action
  • The guide says what OS version and date it was tested on

Support drill

Read an old guide your coach gives you. Find three steps that would confuse a new person and fix them.

Practice rewrites

Try each one before you open the answer.

Rewrite: “Set up SSH and connect to the device.”

Example: “1. On the Pi, run sudo raspi-config → Interface Options → SSH → Yes. 2. On your laptop, type ssh tony@trainpi.local. You should see tony@trainpi:~ $.”

Rewrite: “If it doesn't work, check the settings.”

Example: “Screen shows ‘This site can't be reached’ → the Pi has no network yet. Wait 1 minute. Still there? Run hostname -I; no address → see Network fix-it guide.”

A tester followed your guide and stopped at step 7 for 20 minutes.

That's a gift: step 7 is missing something. Ask what they expected to see, add it (and a ‘you should see’ line), and test again.
