The Big Screen, part 1: kiosk mode

Make a Pi start straight into a full-screen web page, with no desktop showing. That is how DiGiKits demo and dashboard screens work.

📝Update progress on the message board below ↓

Why it matters

A showroom screen must come back on its own after a power cut, with no keyboard and nobody touching it.

Steps

  1. Turn off screen blanking: sudo raspi-config → Display Options → Screen Blanking → No.
  2. Find your desktop type: echo $XDG_SESSION_TYPE (current Raspberry Pi OS uses Wayland with the labwc desktop).
  3. Add the browser to the desktop's autostart file. On labwc it is ~/.config/labwc/autostart: 
    chromium --kiosk --noerrdialogs --disable-infobars https://wdigi.github.io/tony/ &
    If chromium is not found, try chromium-browser. Older setups use a different autostart file; look up your OS version's method.
  4. Reboot and check it comes up full screen.
  5. Hide the mouse pointer and set the screen to never sleep (search your OS version's way; write down what worked).

The kiosk boot chain

Auto-login

The chain needs the Pi to log in by itself: sudo raspi-config → System Options → Boot / Auto Login → Desktop Autologin.

Make the browser wait: a kiosk script

Instead of starting the browser straight from autostart, start a small script that waits until the page can really be reached:

#!/bin/bash
# ~/bin/kiosk.sh
URL="https://wdigi.github.io/tony/"
for i in $(seq 1 60); do                       # wait up to 2 minutes
  curl -s --head --max-time 3 "$URL" >/dev/null && break
  sleep 2
done
exec chromium --kiosk --noerrdialogs --disable-infobars --incognito "$URL"

Then in ~/.config/labwc/autostart: /home/tony/bin/kiosk.sh & (and chmod +x the script). --incognito stops the "Restore pages?" bubble after a power cut.

Checking a kiosk from far away

ssh showroom-pi
pgrep -a chromium                        # is the browser running? which page?
WAYLAND_DISPLAY=wayland-0 grim /tmp/screen.png   # take a screenshot (sudo apt install grim if missing)
exit
scp showroom-pi:/tmp/screen.png .        # look at it on your laptop

A screenshot tells you in ten seconds whether the customer sees the page, an error, or a black screen.

Screen setup

  • Rotate or set resolution: the Screen Configuration tool on the desktop, or wlr-randr in the terminal (wlr-randr alone lists the screens).
  • Updates: kiosk Pis need security updates too. Schedule them at night (Day 2) and reboot after.

Done when

  • Pulling the power and plugging it back in brings the page back full screen
  • You wrote down every step in your own words (you need it on Day 15)
  • You can draw the six-link boot chain from memory
  • Your browser starts from kiosk.sh and waits for the page
  • You took a screenshot of the kiosk over SSH

Support drill

The screen shows "This site can't be reached" after boot. The page works later. Why? (Hint: the network may not be ready yet.)

More cases

Try each one before you open the answer.

After a power cut the page shows a “Restore pages?” bubble.

Chromium thinks it crashed. Start it with --incognito so it doesn't keep a session.

The desktop appears, but no browser.

The autostart file is wrong (path, name, or the script isn't executable). Check ~/.config/labwc/autostart and run the script by hand over SSH to see its error.

The screen goes black after 10 minutes.

Screen blanking is still on, or the TV has its own sleep timer. Check raspi-config, then the TV menu.

The page is sideways on a portrait-mounted screen.

Rotate the output with Screen Configuration or wlr-randr --output HDMI-A-1 --transform 90, then make it permanent the way your OS version does.
