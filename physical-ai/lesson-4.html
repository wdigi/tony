Memory and the CPU: how gates remember and follow instructions

Gates can decide. But a computer also has to remember things and work through a list of instructions, one after another. In this lesson you'll see both: a loop of gates that remembers, and a tiny pretend processor that runs a program you can watch step by step.

Gates that remember

A push button springs back the moment you let go. So how does a machine keep running after you release Start? The trick is to feed the output back into the input. Once the motor is on, it holds itself on, until Stop breaks the loop.

Control panel builders know this as a start/stop “seal-in” circuit. In chips, the same idea is called a latch, and it's how every bit of memory works.

Motor = (Start OR Motor) AND NOT Stop

Push Start, then watch what happens when the button springs back.

That one loop stores one bit: running (1) or stopped (0). Put eight of them side by side and you can store a byte. Put billions together and you have the memory in a Raspberry Pi.

Memory is a row of numbered boxes

Think of memory as a very long street of boxes. Each box holds one byte, and each box has a number, its address, usually written in hex. The CPU says “give me box 0x0004” or “put 0x2D into box 0x0005”.

Support tip: “It worked until the power cut, now my setting is gone” usually means the setting lived only in RAM and was never saved to storage. And pulling the power on a Pi while it's writing to the SD card can corrupt the card. That's why you shut down with sudo shutdown now first.

The CPU: fetch, decode, execute

The processor (CPU) does one simple loop, over and over, forever:

  1. Fetch: read the next instruction from memory. A small counter called the program counter remembers where it is.
  2. Decode: work out what the instruction means.
  3. Execute: do it, then move the program counter on.

Here's a toy CPU running a 4-line program that blinks an LED and counts the blinks. Press Step to go one phase at a time, or Run to watch it go.

One phase per press. A real CPU does this billions of times per second.

This toy runs about one phase per second so you can follow it. A Raspberry Pi 5 ticks about 2.4 billion times per second, on four cores at once. It's the same simple loop; only the speed is unimaginable.

Notice the layers again. The program is stored as bytes (0x11, 0x21…), which are bits, which are latches holding voltages. The words “LED ON” are only there for us. By the people, for the people.

Hands-on

1. Break the loop

In the start/stop drawing: start the motor, then hold your eye on the dashed feedback wire while you press Stop. Explain in one sentence why the motor stays off after Stop springs back.

2. Count in binary

Run the toy CPU until COUNT reaches 10. Before each blink, predict the binary and hex, then check.

3. Look inside your Pi

lscpu          # the CPU: model, number of cores, speed
free -h        # RAM: total, used, free
df -h          # storage: how full the SD card is

Write down your Pi's number of cores, total RAM and SD card size. Post them on the board below.
