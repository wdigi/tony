Physical AI Systems · Lesson 2

Binary, hex and programming languages

In Lesson 1 you saw that, at the bottom, a computer is billions of switches going high and low. This lesson climbs the ladder from those switches up to the languages people actually write in, and shows you the two number systems, binary and hex, that you'll meet every day in DiGiKits support work.

The big idea: languages are for people

Every “computer language” was invented by people, for people. The hardware never reads Python or C. It only ever sees bits switching inside the chip. Everything above that is a ladder of translations, each rung made so that humans can think and work more easily.

The newest rung: plain English. Until recently the top of the ladder for most people was a programming language. Now an AI like Claude can take plain English and write the Python or C for you. That's how DiGiKits builds software today. But the lower rungs don't disappear. When something breaks, a support person still has to read an error, a log line or a hex value from further down the ladder, and that's what this lesson prepares you for.

Binary: counting with only 0 and 1

We count in decimal (base 10) because we have ten fingers: each place is worth ten times the place to its right (ones, tens, hundreds). Binary (base 2) works the same way, but each place is worth two times the place to its right.

Binary is perfect for the chip but hard for people: 11111111 is easy to misread, and a 32-bit number is a wall of 32 digits. So people invented a shorthand.

Hex: a shorthand for binary

Hexadecimal, or hex (base 16), uses sixteen digits: 0–9, then A B C D E F for 10 to 15. The magic is that one hex digit is exactly four bits. So one byte is always exactly two hex digits, and you can convert in your head, four bits at a time.

Hex is binary in disguise. Behind the scenes, hex is binary: 0x2D and 00101101 are exactly the same bits in the chip. Nothing is converted and nothing changes. We write it as hex only because two characters are easier for people to read and type than eight. It's one more layer made for humans. As you work your way towards Physical AI you'll meet many more layers like this, and the logic behind every one of them is simple: by the people, for the people.

One job, four rungs

Here's the same job, “turn on the LED on pin 17,” written on different rungs of the ladder. Notice how each step down is longer and closer to the hardware.

RungWhat it looks likeWho writes it
Plain English“Turn on the LED on pin 17.”You, to Claude
Python (on the Pi)LED(17).on()People or AI; run by the Python interpreter
C (firmware on a microcontroller)gpio_put(17, 1);People or AI; turned into machine code by a compiler
Assembly (simplified)MOV r0, #1 … STR r0, [r1]Rarely written by hand now; produced by the compiler
Machine codebytes like 01 20 08 60 (illustration; real examples in the live session)Never written by hand; this is what the CPU reads

Two ways to go down the ladder:

  • Compiler (C, C++): translates the whole program into machine code before it runs. Fast, and the result runs only on the chip family it was built for.
  • Interpreter (Python): reads and runs your program line by line while it runs. Easier to change and test, a bit slower.

Hands-on

1. Convert by hand

Without a computer: write 45, 100 and 255 in binary, then in hex. Then go the other way: what decimal numbers are 0x3C and 0xFF?

2. Check with Python

Open a terminal on the Pi, type python3, and try:

>>> bin(45)
'0b101101'
>>> hex(45)
'0x2d'
>>> int('ff', 16)
255
>>> int('00101101', 2)
45

Type exit() to leave Python.

3. Colour detective

Search “colour picker”, pick any colour you like, and read its hex code (like #1E90FF). Split it into red, green and blue bytes and work out each one in decimal. Post your colour and the three numbers on the board below.
