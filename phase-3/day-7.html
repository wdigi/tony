Phase 3 · Day 7

Daily checks and lab operations

Run the daily routine that keeps machines healthy: checks, small fixes, and a log.

📝Update progress on the message board below ↓

Why it matters

A lab or a group of client screens needs someone to look every day. Five minutes of checks saves hours of repair.

A daily check

  • Monitoring dashboard: anything red or flapping?
  • Health logs: temperature, disk, power warnings since yesterday?
  • Updates waiting? Schedule them, don't run them blind on live systems.
  • Backups: did last night's backup finish?
  • Open tickets: anything waiting on you?

Practice

Write a daily-check script that prints one summary for all your Pis. Run the check every morning this week and keep an operations log (date, what you checked, what you found, what you did).

A daily check script

#!/bin/bash
# ~/bin/daily.sh - one line per Pi
printf "%-16s %-6s %-8s %-6s %-6s %s\n" HOST UP TEMP DISK POWER FAILED
while read -r h; do
  [ -z "$h" ] && continue
  r=$(ssh -n -o ConnectTimeout=5 -o BatchMode=yes "$h" '
      t=$(vcgencmd measure_temp | cut -d= -f2)
      d=$(df --output=pcent / | tail -1 | tr -d " ")
      p=$(vcgencmd get_throttled | cut -d= -f2)
      f=$(systemctl --failed --no-legend | wc -l)
      echo "$t $d $p $f"' 2>/dev/null)
  if [ -z "$r" ]; then printf "%-16s %s\n" "$h" "DOWN"
  else set -- $r; printf "%-16s %-6s %-8s %-6s %-6s %s\n" "$h" yes "$1" "$2" "$3" "$4"; fi
done < ~/fleet/hosts.txt

The operations log

2026-11-27 08:40  daily check
  lab-test-03: 78.9'C, disk 91 %, throttled 0x50000, kiosk failed → ticket #151
  shop-screen-02: DOWN since 07:12 (Kuma) → ticket #152, called store 08:45
  backups: all 5 finished overnight
  updates: 12 waiting on lab Pis → scheduled for canary Friday

Short, dated, links to tickets. Anyone covering for you reads the last few days and knows what's going on.

The rhythm of lab operations

The spares shelf

The lab keeps known-good spares for the known-good swap (Day 2): flashed SD cards with the golden image, a Pi, power supplies, HDMI cables, a short LED strip, a Pico. Label each with its date and test it monthly. A spare that doesn't work is worse than none.

Handing over

Before time off, write a handover: open tickets and their next steps, anything flapping, anything scheduled while you're away. The person covering reads it and the ops log, and knows where everything stands.

Done when

  • The check runs in under 5 minutes
  • A week of operations log entries
  • daily.sh prints one line per Pi and shows DOWN for an unreachable one
  • Your ops log entries link to tickets
  • You wrote a sample handover note

More cases

Try each one before you open the answer.

The daily check shows the same Pi at 85 % disk every day this week, slowly rising.

Not urgent yet, but a trend. Find what's growing (du -sh /var/log/* /home/*), fix rotation, and note it before it becomes a Severity 1.

A spare SD card from the shelf won't boot.

Remove it from the shelf, re-flash or bin it, and add 'test spares monthly' to your calendar if it isn't already.

Twelve updates are waiting. Install them all now on every Pi?

No: canary first (Phase 2 Day 12), at a quiet time, with a way back.
