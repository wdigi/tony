Phase 3 · Day 4

Remote support sessions

Fix a customer's system from home, safely and with their permission.

📝Update progress on the message board below ↓

Rules that never bend

  • Ask first. Connect only with the customer's permission, and tell them when you start and finish.
  • Never ask for passwords in chat or email. Use the access method set up for that site.
  • Least access: touch only the system the ticket is about.
  • Log it: write down every command that changes something.
  • Customer data is private. Don't copy their files or screenshots anywhere else.

Practice

  1. Your coach plays the customer with a Pi on their network.
  2. Get access the approved way (for example, a Tailscale share they send you).
  3. Find and fix the fault, logging every command.
  4. Undo any temporary access at the end and confirm with the "customer".

A remote session, start to finish

Record every command automatically

The script command writes everything you type and see to a file. Start it at the beginning of every remote session:

Change things you can undo

# before editing any config file, keep a dated copy
sudo cp /etc/systemd/system/kiosk.service /etc/systemd/system/kiosk.service.bak-2026-11-27
# after: compare what you changed
diff /etc/systemd/system/kiosk.service.bak-2026-11-27 /etc/systemd/system/kiosk.service
# and if it went wrong, put it back
sudo cp /etc/systemd/system/kiosk.service.bak-2026-11-27 /etc/systemd/system/kiosk.service
  • Know your way back before every change. If you can't undo it, ask first (Day 8).
  • Don't reboot a customer-facing device during opening hours without asking.
  • Don't leave things half done. If you must stop, put it back how it was, and say so in the ticket.

Done when

  • A full remote session done by the rules, with a clean log
  • Your session log was recorded with script
  • You made a dated backup before editing a file, and showed the diff
  • You ended the session: access removed, customer told, ticket updated

Support drill

The "customer" emails you their password. What do you do?

More cases

Try each one before you open the answer.

Halfway through, you realise your change broke the screen completely.

Put the backup file back, restart, check it's as before. Tell the customer honestly: “My change didn't work, I've put it back as it was. Next I'll try …”. Note it in the ticket.

While fixing the screen you notice their router still has the default admin password.

Not your ticket to fix. Tell the customer (and your coach) in writing, recommend changing it, and offer help if they want it.

The customer stops answering halfway through the session.

Finish only what's safe, or put it back as it was. Leave a written update with where things stand, then remove temporary access as agreed.
