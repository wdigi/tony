Phase 1 · Day 9

Services and logs

Make your program start on its own, and read logs to see what went wrong.

📝Update progress on the message board below ↓

Why it matters

Products must start after a power cut. Logs are where every fault leaves a trace.

Make a service

Create /etc/systemd/system/blink.service with sudo nano:

[Unit]
Description=Blink practice
After=network.target

[Service]
ExecStart=/usr/bin/python3 /home/yourname/practice/blink.py
Restart=on-failure
User=yourname

[Install]
WantedBy=multi-user.target
sudo systemctl daemon-reload
sudo systemctl enable --now blink
systemctl status blink
journalctl -u blink -f        # live log, Ctrl+C to stop

Health checks

df -h                    # disk full?
free -h                  # memory
vcgencmd get_throttled   # 0x0 = no power problems
dmesg | tail -20         # recent hardware messages

The systemctl verbs

CommandDoes
sudo systemctl start blinkStart now (not at boot)
sudo systemctl stop blinkStop now
sudo systemctl restart blinkStop and start, e.g. after changing the script
sudo systemctl enable blinkStart at every boot (--now also starts it now)
sudo systemctl disable blinkDon't start at boot any more
systemctl status blinkIs it running? Last few log lines.
systemctl --failedEvery service that has failed. Run it first on a sick Pi.

After you edit a .service file, always sudo systemctl daemon-reload, then restart the service.

Reading systemctl status

journalctl: the log reader

journalctl -u blink -n 50          # last 50 lines from one service
journalctl -u blink --since "10 min ago"
journalctl -b                      # everything since this boot
journalctl -b -1                   # the boot before (if the journal is kept on disk)
journalctl -p err -b               # only errors, this boot
dmesg -T | tail -20                # hardware and kernel messages with times

Staying up: restart rules

[Service]
ExecStart=/home/tony/venv/bin/python /home/tony/practice/blink.py
Restart=always
RestartSec=5
User=tony

Mistakes that break services

  • Relative paths. A service doesn't start in your home folder. Write full paths everywhere, also for files the script opens.
  • The wrong Python. If the script needs packages from a virtual environment, ExecStart must use that venv's python.
  • Network not ready. Scripts that talk to the network at boot need After=network-online.target and Wants=network-online.target.
  • Forgot daemon-reload after editing: systemd still runs the old version.

Done when

  • Your script runs after sudo reboot without you touching anything
  • You can show the log line where it started
  • You found a failed service with systemctl --failed
  • You read the Loaded and Active lines of a status and explained them
  • You used journalctl with -u, --since and -p err
  • Your service restarts by itself 5 seconds after you kill it (sudo pkill -f blink.py)

Support drill

The service won't start. Read systemctl status and the journal, find the cause, fix it.

More cases

Try each one before you open the answer.

Status shows “status=203/EXEC”.

systemd couldn't run the program at all: the path in ExecStart is wrong, or the file isn't executable. Check the full path with ls -l.

“ModuleNotFoundError: No module named 'neopixel'” in the journal, but the script works when you run it.

You run it with the venv python; the service uses /usr/bin/python3. Point ExecStart at the venv's python.

It works when started by hand, fails only after a reboot.

Usually something isn't ready yet at boot, often the network. Add After=/Wants=network-online.target, and read journalctl -b -u name.

You edited the service file, but nothing changed.

Run sudo systemctl daemon-reload, then sudo systemctl restart name.
