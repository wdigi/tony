Phase 1 · Day 7

Python and the microcontroller

Build a small LED controller the DiGiKits way: a microcontroller drives an LED, a button and an LED strip, and Python on the Pi gives the orders over the network.

📝Update progress on the message board below ↓

Why it matters

DiGiKits products control lights and motors. Support means telling a software fault from a network fault from a wiring fault, so you need to know every link in the chain.

The DiGiKits rule: the Pi never touches hardware. Its 40-pin GPIO header stays empty. Every LED, button, sensor and motor connects to a microcontroller inside a controller, and the computer talks to that controller only over the network.

Python, MicroPython, C/C++: which one where?

You'll hear three names. They are not the same thing, and DiGiKits uses them in different places:

LanguageWhat it isRuns onAt DiGiKits
PythonAn easy-to-read language. Runs inside an operating system.The Pi, laptops, serversYes: scripts, tests, tools, and talking to controllers over the network
MicroPythonA small version of Python squeezed onto a microcontrollerPico and similar boardsNo. It's popular for learning; you'll see it online. You don't have to use it, and we don't.
C/C++The classic language for hardware. Compiled into firmware the chip runs directly.Microcontrollers (Pico 2, RP2350, ESP32…)Yes: all DiGiKits firmware, such as the LED controller

The tools: Arduino, PlatformIO and VS Code

  • Arduino is two things: a simple framework (ready-made functions like setup(), loop(), digitalWrite(), Serial.println()) and a beginner IDE. We use the framework, so code looks like Arduino code you find online.
  • VS Code is the code editor (free, from Microsoft) on your laptop.
  • PlatformIO is an extension for VS Code that builds and uploads firmware. One file, platformio.ini, says which board, which framework and which library versions. That file goes in Git, so the same firmware builds the same way on any computer, years later.

You'll learn C/C++ properly in Phase 2 Day 7. Today you build the whole chain once and see it work.

Just enough Python

You don't need to be a programmer to support DiGiKits systems, but you must read a short script and spot what it does. Five ideas cover most of it:

count = 0                               # a variable: a named box holding a value
colours = ["RGB 255 0 0", "RGB 0 0 255"]    # a list of values
for c in colours:                       # a loop: do this for each one
    print("sending", c)
if count == 0:                          # a decision; indented lines run only if true
    print("nothing counted yet")
def send(cmd):                          # a function: a named recipe you can reuse
    print(">>", cmd)
Indentation is part of the code. Python uses the spaces at the start of a line to know what belongs inside an if, loop or function. Use 4 spaces, never mix with tabs.

Build it: Pi → network → Pico controller

1 · Tools on your laptop (once)

  1. Install VS Code (code.visualstudio.com).
  2. In VS Code: Extensions (the four-squares icon) → search PlatformIO IDE → Install. Wait until it finishes and asks you to reload.
  3. PlatformIO's home page → New Project → name led-controller, board Raspberry Pi Pico, framework Arduino → Finish.
  4. Replace everything in platformio.ini with the lines below. They switch the project to the Pico 2 (RP2350) and the community Arduino core that supports it, and add the LED library with a fixed version:
[env:pico2]
platform = https://github.com/maxgerhardt/platform-raspberrypi.git
board = rpipico2
framework = arduino
board_build.core = earlephilhower
lib_deps = adafruit/Adafruit NeoPixel@^1.12.0
monitor_speed = 115200

2 · The firmware: src/main.cpp

#include <Arduino.h>
#include <Adafruit_NeoPixel.h>

// Serial  = USB: for testing on the bench with the Serial Monitor
// Serial1 = UART on GP0 (TX) and GP1 (RX): wired to the network module
const int STRIP_PIN  = 2;     // GP2  → 330 Ω → strip DIN
const int NUM_LEDS   = 30;
const int LED_PIN    = 15;    // GP15 → 330 Ω → LED long leg; short leg → GND
const int BUTTON_PIN = 14;    // GP14 → button → GND
Adafruit_NeoPixel strip(NUM_LEDS, STRIP_PIN, NEO_GRB + NEO_KHZ800);

void handle(Stream &port, String cmd) {
  int i, r, g, b, on;
  if (cmd == "OFF")       { strip.clear(); strip.show(); }
  else if (cmd == "SHOW") { strip.show(); }
  else if (sscanf(cmd.c_str(), "RGB %d %d %d", &r, &g, &b) == 3)     { strip.fill(strip.Color(r, g, b)); strip.show(); }
  else if (sscanf(cmd.c_str(), "PIX %d %d %d %d", &i, &r, &g, &b) == 4) { strip.setPixelColor(i, strip.Color(r, g, b)); }
  else if (sscanf(cmd.c_str(), "LED %d", &on) == 1)                   { digitalWrite(LED_PIN, on ? HIGH : LOW); }
  else { port.println("ERR " + cmd); return; }
  port.println("OK " + cmd);
}

void listen(Stream &port) {
  if (!port.available()) return;
  String cmd = port.readStringUntil('\n');
  cmd.trim();
  if (cmd.length()) handle(port, cmd);
}

void setup() {                         // runs once at power-on
  Serial.begin(115200);
  Serial1.setTX(0); Serial1.setRX(1);
  Serial1.begin(115200);               // must match the network module's serial settings
  pinMode(LED_PIN, OUTPUT);
  pinMode(BUTTON_PIN, INPUT_PULLUP);   // pin reads HIGH until the button joins it to GND
  strip.begin();
  strip.setBrightness(40);             // about 15 %: low current while learning
  strip.show();
}

void loop() {                          // runs again and again, forever
  listen(Serial);                      // commands typed in the Serial Monitor
  listen(Serial1);                     // commands from the network
  static int last = HIGH;
  int now = digitalRead(BUTTON_PIN);
  if (last == HIGH && now == LOW) {    // just pressed
    Serial.println("BUTTON");
    Serial1.println("BUTTON");
    delay(30);                         // ignore contact bounce (Phase 2 shows a better way)
  }
  last = now;
}

Read it like a recipe: setup() runs once at power-on; loop() runs again and again. Each time round it checks both doors (USB and the network module) for a command line, answers OK or ERR, and reports BUTTON when the button is pressed. Commands: LED 1, LED 0, RGB r g b, PIX i r g b + SHOW, OFF.

3 · Wire it (power off)

The strip follows Day 8's power rules: its own 5 V supply, grounds joined. Haven't got the strip parts yet? Wire the LED, button and module now, the strip after Day 8.

4 · Upload and test on the bench (USB)

  1. First upload only: hold the Pico's BOOTSEL button while plugging its USB cable into your laptop, then let go.
  2. Click → Upload in VS Code's bottom bar. PlatformIO downloads its tools the first time (a few minutes), compiles and uploads. Later uploads work without BOOTSEL.
  3. Click the plug icon (Serial Monitor). Type LED 1 and press Enter: the LED lights and you see OK LED 1. Press the button: you see BUTTON.

USB is only for uploading and bench tests. In a real installation the controller is reached over the network.

5 · Put the controller on the network

  1. Plug the module's Ethernet into a LAN port of your lab router (Day 6) and power it as its guide says.
  2. Open the router's Devices page. Find the new device by its MAC (on the module's label) and reserve 192.168.50.60 for it.
  3. Open the module's own settings page in a browser at that address. Set: work mode TCP server, local port 5000, serial 115200, 8 data bits, no parity, 1 stop bit (8N1, Physical AI Lesson 7). Save and restart it. Menu names differ between modules; your coach's module guide has the exact screens.
  4. Power off, then wire the module's serial pins to the Pico (drawing above): module RX ← GP0, module TX → GP1, GND to GND. Check the module's serial pins are 3.3 V level, like the Pico's.

Test from your laptop before writing any Python: nc 192.168.50.60 5000, type LED 1, Enter. OK LED 1 came back over the network. (That's exactly how the fake controller in Phase 2 Day 5 behaves.)

6 · Python on the Pi gives the orders

# ~/practice/controller.py  - talk to the LED controller over the network
import socket

CONTROLLER = ("192.168.50.60", 5000)   # the network module's reserved IP, and its port

def connect():
    ctl = socket.create_connection(CONTROLLER, timeout=3)
    ctl.settimeout(None)                # connected: now wait as long as needed
    return ctl.makefile("rw", newline="\n")

def send(f, cmd):
    f.write(cmd + "\n")
    f.flush()
    while True:                         # skip BUTTON lines; wait for OK or ERR
        reply = f.readline().strip()
        if not reply or reply.startswith(("OK", "ERR")):
            return reply
# ~/practice/blink.py  - blink the controller's LED from the Pi
import time
from controller import connect, send

f = connect()
for i in range(10):
    print(send(f, "LED 1")); time.sleep(0.5)
    print(send(f, "LED 0")); time.sleep(0.5)
# ~/practice/button.py  - each button press on the controller flips its LED
from controller import connect, send

f = connect()
led_on = False
while True:
    line = f.readline().strip()
    if not line:
        break                           # connection closed
    if line == "BUTTON":
        led_on = not led_on
        print("pressed →", send(f, "LED 1" if led_on else "LED 0"))

All three files go in ~/practice on the Pi. python3 blink.py blinks the controller's LED; python3 button.py waits for presses (Ctrl+C to stop). Python's socket is built in: nothing to install.

Support drill

Your coach breaks one link in the chain (firmware, serial wires, module settings, network, or the script). Find which one, testing near to far: Serial Monitor, then nc from the laptop, then the Python script.

More cases

Try each one before you open the answer.

The Serial Monitor works, but nc 192.168.50.60 5000 gets no reply to LED 1.

Firmware is fine; the break is between the module and the Pico. Check TX/RX aren't swapped (module RX ← GP0, module TX → GP1), the grounds are joined, and the module's serial settings are 115200 8N1.

Replies come back as strange characters.

Speed mismatch: the module and the firmware use different baud rates. Both must be 115200 (Physical AI Lesson 7, the wrong-baud box).

“Connection timed out” from the Pi.

Nothing answered at that address: the module is off, unplugged, or got a different IP. Check the router's Devices page and the reservation (Day 6).

“Connection refused”.

The module answered, but isn't listening on port 5000: check its work mode (TCP server) and local port.

The upload fails: “no device found”.

First upload needs BOOTSEL held while plugging in. Also try another USB cable: some only charge.

OK LED 1 comes back, but the LED stays dark.

Software and network are fine, so it's the wiring: LED backwards (long leg towards GP15), resistor in the wrong row, or the wrong pin.
