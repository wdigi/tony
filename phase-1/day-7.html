Phase 1 · Day 7

Python and GPIO

Make the Pi control real hardware: an LED, a button, and an LED strip.

📝Update progress on the message board below ↓

Why it matters

DiGiKits products control lights and motors. Support means telling a software fault from a wiring fault.

Blink an LED

Wire GPIO17 → 330 Ω resistor → LED long leg; LED short leg → GND. Power off while wiring.

from gpiozero import LED, Button
from signal import pause

led = LED(17)
button = Button(27)        # button between GPIO27 and GND

button.when_pressed = led.on
button.when_released = led.off
pause()

Save as ~/practice/blink.py and run python3 ~/practice/blink.py. Ctrl+C to stop.

Python, MicroPython, C/C++: which one where?

You'll hear three names. They are not the same thing, and DiGiKits uses them in different places:

LanguageWhat it isRuns onAt DiGiKits
PythonAn easy-to-read language. Runs inside an operating system.The Pi, laptops, serversYes: scripts, tests, tools, talking to boards, today's GPIO work
MicroPythonA small version of Python squeezed onto a microcontrollerPico and similar boardsNo. It's popular for learning; you'll see it online. You don't have to use it, and we don't.
C/C++The classic language for hardware. Compiled into firmware the chip runs directly.Microcontrollers (Pico 2, RP2350, ESP32…)Yes: all DiGiKits firmware, such as the LED controller

The tools: Arduino, PlatformIO and VS Code

  • Arduino is two things: a simple framework (ready-made functions like setup(), loop(), digitalWrite(), Serial.println()) and a beginner IDE. We use the framework, so code looks like Arduino code you find online.
  • VS Code is the code editor (free, from Microsoft) on your laptop.
  • PlatformIO is an extension for VS Code that builds and uploads firmware. One file, platformio.ini, says which board, which framework and which library versions. That file goes in Git, so the same firmware builds the same way on any computer, years later.

You'll learn C/C++ properly in Phase 2 Day 7. Today you just see the whole chain work once.

Just enough Python

You don't need to be a programmer to support DiGiKits devices, but you must read a short script and spot what it does. Five ideas cover most of it:

count = 0                     # a variable: a named box holding a value
if button.is_pressed:         # a decision; the indented lines run only if true
    count = count + 1
for i in range(3):            # a loop: do this 3 times
    led.blink(on_time=0.2, off_time=0.2, n=1, background=False)
def flash(times):             # a function: a named recipe you can reuse
    led.blink(n=times, background=False)
print("count is", count)      # show something in the terminal
Indentation is part of the code. Python uses the spaces at the start of a line to know what belongs inside an if, loop or function. Use 4 spaces, never mix with tabs.

How the button input works

Button(27) turns on the Pi's built-in pull-up: GPIO27 is held at 3.3 V (reads "not pressed") until the button joins it to GND (reads "pressed"). That's why the button goes between the pin and GND, with no resistor. Real buttons also "bounce": one press makes several quick contacts. bounce_time ignores the extras.

Example: Pi + Pico 2 + WS2812

This is how DiGiKits lighting is built: the Pi does the thinking and talks to the network, the microcontroller drives the LEDs with exact timing. They talk over a USB cable using short text commands, one per line.

1 · Set up the tools (laptop, once)

  1. Install VS Code (code.visualstudio.com).
  2. In VS Code: Extensions (the four-squares icon) → search PlatformIO IDE → Install. Wait until it finishes and asks you to reload.
  3. PlatformIO's home page → New Project → name pico-leds, board Raspberry Pi Pico, framework Arduino → Finish.
  4. Open platformio.ini and replace everything in it with the lines below. They switch the project to the Pico 2 (RP2350) and the community Arduino core that supports it, and add the LED library with a fixed version:
[env:pico2]
platform = https://github.com/maxgerhardt/platform-raspberrypi.git
board = rpipico2
framework = arduino
board_build.core = earlephilhower
lib_deps = adafruit/Adafruit NeoPixel@^1.12.0
monitor_speed = 115200

2 · The firmware: src/main.cpp

#include <Arduino.h>
#include <Adafruit_NeoPixel.h>

const int LED_PIN  = 0;     // GP0 → 330 Ω → strip DIN
const int NUM_LEDS = 30;
Adafruit_NeoPixel strip(NUM_LEDS, LED_PIN, NEO_GRB + NEO_KHZ800);

void setup() {                       // runs once at power-on
  Serial.begin(115200);              // USB serial link to the Pi
  strip.begin();
  strip.setBrightness(40);           // about 15 %: low current while learning
  strip.show();                      // all off
}

void loop() {                        // runs again and again, forever
  if (!Serial.available()) return;
  String cmd = Serial.readStringUntil('\n');
  cmd.trim();
  int r, g, b;
  if (cmd == "OFF") {
    strip.clear();
  } else if (sscanf(cmd.c_str(), "RGB %d %d %d", &r, &g, &b) == 3) {
    strip.fill(strip.Color(r, g, b));
  } else {
    Serial.println("ERR " + cmd);
    return;
  }
  strip.show();
  Serial.println("OK " + cmd);
}

Read it like a recipe: setup() runs once when the board powers on; loop() runs again and again. Each time round, if a line has arrived from the Pi, it changes the colours and answers OK.

3 · Wire it (power off)

Same three wires as Day 8, but from the Pico: GP0 → 330 Ω resistor → strip DIN; strip 5 V and GND to the strip's own 5 V supply; Pico GND joined to the supply's GND. The Pico is powered by its USB cable from the Pi. Haven't got the strip parts yet? Do steps 1–2 and 4 now, and the wiring after Day 8.

4 · Upload and test

  1. First upload only: hold the Pico's BOOTSEL button while plugging its USB cable into your laptop, then let go.
  2. Click the → Upload arrow in VS Code's bottom bar. PlatformIO downloads the tools the first time (a few minutes), compiles and uploads. After this, uploads work without BOOTSEL.
  3. Click the plug icon (Serial Monitor). Type RGB 0 40 0 and press Enter. The strip turns green and the monitor shows OK RGB 0 40 0.

5 · Let the Pi drive it

Close the Serial Monitor (only one program can use the port at a time), move the Pico's USB cable to the Pi, and run this on the Pi:

# on the Pi:  sudo apt install -y python3-serial
import serial, time

pico = serial.Serial("/dev/ttyACM0", 115200, timeout=2)
time.sleep(2)                                   # give the Pico a moment after connecting
for cmd in ["RGB 255 0 0", "RGB 0 0 255", "RGB 255 140 60", "OFF"]:
    pico.write((cmd + "\n").encode())
    print(cmd, "→", pico.readline().decode().strip())   # expect: OK …
    time.sleep(1)

Your user needs the dialout group to open /dev/ttyACM0 (Day 5). Phase 2 extends this chain: commands from the network to the Pi, to the Pico, to the lights.

Support drill

The LED won't light. Is it the code, the pin number, the LED direction, or a loose wire? Find it.

More cases

Try each one before you open the answer.

“GPIOPinInUse: pin GPIO17 is already in use.”

Another program holds the pin, often your Day 9 service or an old script still running. Find it: ps aux | grep python. Stop the service (sudo systemctl stop blink) or end the old script.

“IndentationError: unexpected indent” on line 6.

Line 6 has extra spaces or a tab where Python didn't expect them. Make the indentation match the lines around it, 4 spaces per level.

Each button press counts 2 or 3 times.

Contact bounce. Use Button(27, bounce_time=0.05).

The script works with sudo but not without.

Permission on the GPIO device: the user isn't in the gpio group (Day 5). Fix the group; don't run it as root.

Pico example cases

Try each one before you open the answer.

The upload fails: “no device found” or it hangs waiting for the board.

First upload needs BOOTSEL held while plugging in. Also try another USB cable: some only charge and carry no data.

On the Pi: “could not open port /dev/ttyACM0: Permission denied”.

Add the user to dialout and log in again: sudo usermod -aG dialout $USER.

On the Pi: “Device or resource busy”.

Another program has the port open, usually a Serial Monitor or a second copy of the script. Close it, then try again.

The Pico answers OK, but the strip stays dark.

The firmware works, so look at the wiring: strip supply on? Grounds joined? Data into the DIN end (arrows)? GP0 really the pin you used?
