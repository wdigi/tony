How the check is scored

A finished support note looks like this

Device: trainpi (lab) · Date: …
Symptom: LED pattern stopped after reboot; SSH works.
Checks: power 0x0 ✓, disk 34 % ✓, network ✓, systemctl --failed → blink.service failed.
Cause: journal shows ModuleNotFoundError: service used system python, packages are in venv.
Fix: ExecStart changed to /home/tony/venv/bin/python, daemon-reload, restart. Rebooted twice: starts by itself.
Prevent: setup guide now says to use the venv python in services.

Warm-up cases

Try each one before you open the answer.

Practice: the Pi boots, but SSH by name fails and by IP works.

Name lookup on the local network (.local / mDNS) is the problem, not SSH. Check the hostname (hostname) matches what you type; check you're on the same network.

Practice: the Pi gets an IP, ping 8.8.8.8 works, apt update fails.

DNS (Day 6 ladder), or the clock is badly wrong so secure connections fail. Check ping google.com and date.

Practice: the LED script runs by hand, but the service is “failed” and nothing is in the journal after “Started”.

Run journalctl -u name -b --no-pager to see the whole log, and check User=: the script may not reach the controller at boot (network not ready yet), or a path is wrong.
