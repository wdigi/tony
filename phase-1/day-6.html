Phase 1 · Day 6

Networking basics

Find any device on a network, know it by its MAC and IP address, and keep a small network in order.

📝Update progress on the message board below ↓

Why it matters

"It's not connecting" is usually a network question first.

Two addresses: MAC and IP

Every device that joins a network has two addresses. Support people use both every day.

MAC addressIP address

You may also hear it called the hardware address, physical address, Wi-Fi address or Ethernet address. Same thing.

Reading a MAC address

Raspberry Pi boards use a few maker codes, such as b8:27:eb on older boards and dc:a6:32 on the Pi 4. You don't need to memorise them: the network scan below and online "MAC vendor lookup" sites show the maker name for you.

Find a MAC

ip link                          # each interface; the MAC is after "link/ether"
cat /sys/class/net/eth0/address  # just the Ethernet MAC
cat /sys/class/net/wlan0/address # just the Wi-Fi MAC
nmcli device show wlan0          # MAC, IP, gateway, DNS in one list

On a Mac: ifconfig en0 | grep ether. On Windows: ipconfig /all ("Physical Address"). On an iPhone or iPad: Settings, Wi-Fi, tap ⓘ next to the network.

One Pi, two MACs

The MAC belongs to the network chip, not the whole device. A Pi has two: one for Ethernet (eth0) and one for Wi-Fi (wlan0). It can even have two IPs at once if both are connected.

Phones and iPads hide their real MAC. iPhones, iPads and Android phones use a made-up "private" Wi-Fi address, different on each network and sometimes changing over time. That breaks reservations and router allow-lists. For a client's iPad that runs a DiGiKits app, set Private Wi-Fi Address to Fixed or Off for that network (the names vary by iOS version). A Pi uses its real MAC unless someone changes it.

How MAC and IP work together

When data leaves your network, the router takes over. The IP stays the same all the way to the far end, while the MAC is only used for the next hop. That is why you never see a website's MAC address: MACs stay inside the local network.

Practice

hostname -I               # this Pi's IP address
ip a                      # all network interfaces
ip route                  # the router (default gateway)
ping -c 4 8.8.8.8         # is the internet reachable?
ping -c 4 google.com      # is DNS working too?
ping trainpi.local        # reach a Pi by name

Also try:

ip neigh                         # devices this Pi has talked to: IP and MAC
nmcli device status              # which connections are up: ethernet, wifi
sudo apt install -y nmap
sudo nmap -sn 192.168.1.0/24     # list every device on your network, with MAC and maker
Scan only networks you own. At a client site, ask their IT person first. A scan can set off their security alarms.

In ip a you'll also see lines starting with inet6 and fe80::. Those are IPv6, the newer, longer kind of address. You can ignore them for now.

Subnets: who can talk directly

192.168.1.0/24 means "every address from 192.168.1.0 to 192.168.1.255". The /24 says the first 24 bits (the first three numbers) are the street. Older screens show the same thing as a subnet mask: 255.255.255.0. A /24 holds 254 devices, because .0 names the street itself and .255 means "everyone" (broadcast).

Devices on different streets can only reach each other through a router. So if a laptop is on 192.168.0.x and the Pi is on 192.168.1.x, they can't see each other, even in the same room.

Addresses worth knowing

AddressWhat it means
192.168.x.x, 10.x.x.x, 172.16.x.x to 172.31.x.xPrivate ranges, used inside homes and offices. Not reachable from the internet.
169.254.x.xThe device asked for an address and no router answered. Check the cable, the Wi-Fi name and password, and the router. (A Pi often shows no IPv4 address at all instead; same meaning.)
127.0.0.1 (localhost)The device itself. Never another machine.
x.x.x.1 or x.x.x.254Usually the router (gateway). ip route tells you for sure.
8.8.8.8, 1.1.1.1Public DNS servers (Google, Cloudflare). Handy ping targets.

A fixed address

Fixed address: the simplest way is a DHCP reservation in your router, so the Pi always gets the same IP. On the Pi itself, sudo nmtui can also set one.

Reservation, static IP, and conflicts

  • Reservation (preferred): in the router's DHCP settings, tie the device's MAC to an IP. Use the MAC of the connection it really uses: Ethernet or Wi-Fi.
  • Static IP: typed into the device itself. Pick an address outside the router's DHCP pool. If the pool is .100 to .199, use something like .20. A static IP inside the pool will one day clash with a device the router hands it to.
  • IP conflict: two devices with one IP. Both drop in and out, often every few minutes. Find the two MACs with ip neigh or a scan, then move one.

Network admin basics

A network admin keeps a network known and tidy: every device has a name, an owner and a place. At DiGiKits you'll do this for our own lab and help clients with theirs.

Find every device

  1. The router's device list (often "DHCP clients" or "Connected devices"): name, MAC and IP of everything that asked for an address. Log in at the router's IP in a browser.
  2. A scan with nmap -sn (above) finds devices that have a static IP too.
  3. Match each line to a real thing. The maker code tells you "this is a Pi" or "this is an Espressif chip" (used in many smart devices and controllers). Unknown device? Unplug things one at a time and see what disappears.

Rules at a client site

  • The network belongs to the client. Ask before you scan, add reservations or change settings. Write down what you changed.
  • Guest Wi-Fi blocks devices from seeing each other ("client isolation"), and is often a different subnet. An iPad on guest Wi-Fi can't reach a controller on the main network. Names ending in .local also don't cross between networks.
  • Many small devices only speak 2.4 GHz Wi-Fi (most ESP32-based boards, for example). If the client's Wi-Fi is 5 GHz only, they won't even see it.
  • Never open ports on a client's router to reach a Pi from outside. We use Tailscale for that (Day 4).
  • MAC filtering is not security. A MAC can be copied in one command. Real security is a strong Wi-Fi password, updates and closed ports.
  • Bigger offices split one physical network into separate ones called VLANs (for example staff, guests, cameras). If two devices on the same switch can't see each other, ask IT which VLAN each one is on.

A home router's admin pages

Every home router has a small website inside it: the admin pages. You open it in a browser at the router's IP (usually 192.168.0.1, 192.168.1.1 or a web name printed on the router's label) and log in with the admin password. Brands lay it out differently, but the same pages are always there.

Monitoring: what to look at

  • Signal (Wi-Fi devices) in dBm. Closer to 0 is stronger: −50 is great, −65 is fine, below −75 expect dropouts. A weak LED controller behind a metal cabinet shows up here first.
  • Traffic: who is using the bandwidth right now. Useful when "the internet is slow".
  • Uptime of the router: if it restarted at 3 a.m., that's your answer to "everything went offline last night".
  • The log: a device that joins and leaves every few minutes has a power or signal problem.

Router safety checklist

  • Change the admin password from the default.
  • Remote management (admin from the internet): off.
  • WPS: off. UPnP: off unless something really needs it.
  • No port forwarding. We reach devices through Tailscale.
  • Firmware up to date. Back up the settings after changes.

Lab: build your own network

Today you become the admin of a small network of your own. A lab router sits behind the home router, so nothing you do can break the family's internet.

You need

  • A lab router: any home Wi-Fi router with a WAN (or "Internet") port and LAN ports. An old one is fine. Your coach will tell you which one to use.
  • Your two Pis, your laptop and your desktop.
  • Three Ethernet cables: home router to lab router, lab router to pi-a, lab router to desktop.
Don't touch the home router's settings. You only plug a cable into one of its spare LAN ports. Everything you change today is on the lab router.

Part A · Start clean (20 min)

  1. Power on the lab router without the WAN cable. If it was used before, hold the reset pinhole for about 10 seconds to return it to factory settings.
  2. Read the label underneath: default Wi-Fi name and password, admin address, admin login. Take a photo for yourself (not the message board).
  3. Plug the laptop into a LAN port, or join the default Wi-Fi. Open the admin address in a browser.

Part B · First setup (30 min)

  1. Set a strong admin password when the setup wizard asks.
  2. Internet / WAN type: Dynamic IP (also called DHCP or Automatic). The home router will give it an address.
  3. Check the operating mode is Router, not "Access point" or "Bridge".
  4. LAN settings: change the router's IP to 192.168.50.1 (mask 255.255.255.0). Set the DHCP pool to .100 to .199. The router restarts; browse to http://192.168.50.1 again.
  5. Wi-Fi: name DGK-LAB, WPA2/WPA3, a new password.
  6. Now plug the cable from a spare LAN port of the home router into the lab router's WAN port.

Why change to 192.168.50.x? Many routers come set to the same addresses as your home router. If the lab router's WAN and LAN are on the same street, it can't route between them and nothing gets internet. Different streets fix it.

Part C · Join the four devices (30 min)

  1. pi-a and the desktop: Ethernet cables into LAN 1 and LAN 2.
  2. pi-b: join DGK-LAB with sudo nmtui → Activate a connection. If pi-b was on Ethernet before, unplug that cable.
  3. Laptop: join DGK-LAB Wi-Fi.
  4. On each Pi, check it landed on the lab street and reaches the internet through two routers: 
    hostname -I                 # 192.168.50.x
ip route                    # default via 192.168.50.1
ping -c 3 8.8.8.8
sudo apt install -y traceroute
traceroute -n 8.8.8.8       # hop 1: 192.168.50.1 (lab), hop 2: 192.168.1.1 (home)

Part D · Manage (60 min)

  1. Open Devices. Find all four. Match each line to a device using the MACs you read with cat /sys/class/net/eth0/address (pi-a) and …/wlan0/address (pi-b). Rename them: pi-a, pi-b, desktop, laptop.
  2. Any line you can't match? Find it (often a phone that joined by itself) or block it.
  3. Add reservations outside the pool: pi-a → 192.168.50.50 (its Ethernet MAC), pi-b → 192.168.50.51 (its Wi-Fi MAC).
  4. Reboot both Pis (sudo reboot). Check they came back on .50 and .51.
  5. From the laptop: ssh pi-a@192.168.50.50 (use your Pi's user name). From pi-a: ping 192.168.50.51.
  6. Go through the safety checklist above.

Part E · Monitor (45 min)

  1. Start a big download on pi-a, then watch the router's traffic numbers: 
    curl -o /dev/null https://speed.cloudflare.com/__down?bytes=200000000
    pi-a should jump to the top. Stop it with Ctrl+C.
  2. Note pi-b's Wi-Fi signal. Carry pi-b to the far end of the home (or behind a closed door) and check again.
  3. Unplug pi-a's cable for a minute, plug it back. Find both events in the log.
  4. Block the laptop. Try a website on it. Unblock it.
  5. Turn on the guest network with isolation. Move the laptop to it and try ping 192.168.50.50. It fails: that is the client-site guest Wi-Fi problem, now you've seen it yourself. Move the laptop back.

Part F · Prove the walls (15 min)

  1. From a phone on the home Wi-Fi, try to open http://192.168.50.1 or ping pi-a. It doesn't work: the lab router hides the lab street behind its one WAN address (this is called NAT). That's also why nobody on the internet can reach your Pi, and why we use Tailscale instead of opening ports.
  2. Back up the router settings. Fill in a network sheet for the lab (keep it private).

Done when

  • You can explain: IP address, router, DHCP, DNS
  • You can explain MAC vs IP, and why your Pi has two MACs
  • You found your Pi's Ethernet and Wi-Fi MACs, and the maker code says Raspberry Pi
  • You can read your router's device list and match every line to a real device
  • Your Pi keeps the same IP after a reboot (a reservation by MAC)
  • You can say what 169.254.x.x means, and why 192.168.0.x can't reach 192.168.1.x
  • You made a network sheet for your home network (kept private)
  • You can name the six admin pages and what each is for
  • Your lab router runs 192.168.50.x behind the home router, admin password changed
  • All four devices are named on the router; pi-a and pi-b keep .50 and .51 after a reboot
  • traceroute from a Pi shows two hops: lab router, then home router
  • You watched traffic, signal and the log, and you blocked and unblocked a device
  • You showed that guest Wi-Fi can't reach the Pis

Support drill

The Pi can ping 8.8.8.8 but not google.com. What is broken? Fix it.

More cases

Try each one before you open the answer.

“We reserved the Pi at .50, but today it's at .87.”

The reservation is for the Ethernet MAC, but the Pi is on Wi-Fi today, so it has a different MAC. Check with nmcli device status. Fix: plug the cable back in, or add a reservation for the Wi-Fi MAC too.

“The iPad app can't find the LED controller. Both are on Wi-Fi.”

Compare the two IPs. If the iPad is on the guest network (different subnet, or client isolation), they can't see each other. Move the iPad to the same Wi-Fi as the controller.

A new controller shows 169.254.12.7.

No router answered. Check the Wi-Fi name and password, and that the network is 2.4 GHz if the controller needs it. For Ethernet, check the cable and the switch port lights.

Two devices keep dropping off every few minutes.

Probably an IP conflict: someone gave one of them a static IP inside the DHCP pool. Find both MACs with ip neigh or a scan, then reserve or move one outside the pool.

Lab router set up, but no device behind it gets internet.

Open Status. No WAN IP: check the cable goes into the WAN port and WAN type is Dynamic IP. WAN IP on the same street as the LAN (both 192.168.1.x): change the LAN to 192.168.50.x.

“I can't open the router page any more.”

Check your device's IP and gateway first (ip route, or the Wi-Fi details on a laptop). You must be on the router's own network, and the address is the gateway. After a LAN IP change the old address no longer works. Last resort: factory reset, then set it up again from your notes.
