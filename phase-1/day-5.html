Phase 1 · Day 5

Users, permissions, packages

Understand who can do what on a Linux computer, and install software safely.

📝Update progress on the message board below ↓

Why it matters

"Permission denied" is one of the most common faults you will see.

Practice

whoami ; groups           # who am I, which groups?
ls -l                     # -rw-r--r-- = owner / group / everyone
chmod +x myscript.sh      # make a script runnable
sudo chown yourname file  # change the owner
sudo cat /etc/shadow      # sudo = run as admin; use it carefully

apt search htop           # find software
sudo apt install htop     # install
htop                      # try it (q to quit)
sudo apt remove htop      # remove

Permissions as numbers

You'll often see permissions written as three digits, like 755. Each digit is one group: owner, group, everyone. Add up what's allowed:

NumberLettersUse it for
755rwxr-xr-xScripts and folders everyone may use, only the owner changes
644rw-r--r--Normal files
600rw-------Private files: keys, passwords, tokens
777rwxrwxrwxNever. Anyone can change it.

Folders need x to go inside them. A folder with r but no x lets you see names but not open anything.

Groups that matter

groups                          # which groups am I in?
sudo usermod -aG dialout,video tony  # add tony to two groups (-a = add, keep the others!)
# log out and back in (or reboot): groups only change at login
Forget -a and you remove the user from every other group, including sudo. Always -aG.

Users and sudo

sudo adduser support        # create a user (asks for a password)
sudo usermod -aG sudo support   # make them an admin
sudo deluser support        # remove the user
sudo -l                     # what may I run with sudo?

sudo runs one command as root, the all-powerful admin. Use it only when needed, and never work in a root shell (sudo -i) for longer than you must.

Packages in more depth

CommandDoes
sudo apt updateRefresh the list of what's available (installs nothing)
sudo apt full-upgradeInstall all updates
apt show htopWhat is this package, which version?
apt list --installed | grep python3Is it installed?
sudo apt autoremoveRemove leftovers nobody needs

Python packages: on Raspberry Pi OS, pip install something stops with externally-managed-environment. That's on purpose, to protect the system. Install the apt version (sudo apt install python3-requests) or make a project folder with its own Python: python3 -m venv .venv then .venv/bin/pip install requests.

Where things live

Done when

  • You can explain the 10 letters in -rwxr-xr--
  • You fix a "permission denied" on a script your coach gives you
  • You can turn 755, 644 and 600 into letters and back
  • You added yourself to the dialout group with -aG and saw it after logging in again
  • You created and removed a second user
  • You installed a Python package the right way (apt or a venv)

Support drill

A program can't write its log file. Find the permission problem and fix it without using chmod 777.

More cases

Try each one before you open the answer.

A script says “Permission denied: /dev/ttyACM0” when talking to a Pico on USB.

The user isn't in the dialout group. sudo usermod -aG dialout username, then log out and in. Don't run it with sudo just to make the error go away.

pip install says “externally-managed-environment”.

Use sudo apt install python3-<name>, or a virtual environment (python3 -m venv .venv). Don't force it with --break-system-packages on a customer's device.

You can see a folder's file names but can't open any file in it.

The folder has r but not x for you. Fix the folder: chmod u+x foldername (or for the group, g+x).

After a usermod, the user can't use sudo any more.

Someone ran usermod -G without -a, which replaced all groups. Log in as another admin and add sudo back: sudo usermod -aG sudo username.
