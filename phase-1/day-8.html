Phase 1 · Day 8

LED strip

Drive a WS2812 LED strip, the same kind DiGiKits LED controllers use.

📝Update progress on the message board below ↓

Why it matters

Most lighting faults are power or wiring, not code. Today you learn to tell them apart.

Setup

  • Power the strip from its own 5 V supply, not the Pi. Connect the grounds together.
  • The Pi 5 needs a Pi 5–compatible LED strip library; the older rpi_ws281x library does not support it. Choose the library with your coach.
  • Install extra Python packages in a virtual environment: python3 -m venv ~/venv then ~/venv/bin/pip install ...
  • Check the arrow on the strip: data flows one way. Solder wires to the input end if needed.

    • How the strip reads its colours

    Each LED on a WS2812 strip has a tiny chip inside. The controller sends one long stream of bits down the data wire. The first LED keeps the first 24 bits for itself (8 for green, 8 for red, 8 for blue), and passes the rest on. The second LED keeps the next 24, and so on.

    Colour(Red, Green, Blue)
    Red(255, 0, 0)
    Warm white-ish(255, 140, 60)
    Full white(255, 255, 255) (most power)
    Off(0, 0, 0)

    Some strips expect the numbers in a different order (GRB instead of RGB). If you ask for red and get green, the colour order setting in your code is wrong, not the strip.

    Power math

    Signs of a professional installation

    • A capacitor (around 1000 µF) across + and − at the strip's input softens the power surge when it switches on.
    • A small resistor (300–500 Ω) in the data wire, near the strip, protects the first LED and cleans up the signal.
    • A level shifter: the Pi sends 3.3 V data, the strip runs on 5 V. Short wires usually work anyway; controllers built for real installs boost the signal to 5 V so it stays reliable.
    • Power injection: long strips get power at both ends (or every few metres), or the far end turns yellow and dim.

    Done when

    • The strip runs three colour patterns you wrote
    • You can explain why the strip has its own power supply
    • You can explain how one data wire controls every LED
    • You worked out the worst-case current for your strip
    • You know what colour order, capacitor, data resistor and power injection are for

    Support drill

    Half the strip shows wrong colours. Is it power, ground, the data line, or the code? Find it.

    More cases

    Try each one before you open the answer.

    You ask for red and the strip shows green.

    Colour order. Your strip is GRB and the code is set to RGB (or the other way round). Change the order setting in the library.

    The far end of a long strip looks yellow and dim on full white.

    Voltage drop: the thin copper in the strip loses voltage over distance. Feed power at both ends too, or lower the brightness.

    The strip flickers random colours.

    Check the shared ground first, then the data wire length and the data resistor. Random colours usually mean the data signal is noisy.

    Only the first few LEDs work; the rest stay dark.

    The LED where it stops (or the joint just before it) is damaged, so the data stops there. Bridge or cut out that LED and re-join.
